# Project 2: re-asking and split-commit attacks on multi-agent oversight

Code, configs, aggregate results and figure scripts for our Project 2 study. This is a release snapshot made on 2026-11-09 from the Apart "Swarm Alignment"
hackathon workspace. Nothing here calls an API unless you run an experiment script with a key.

## Overview

The paper has two studies of one question: what happens when an attack is spread across steps?

1. **Re-asking / delegation (Plan D).** A coordinator passes a user's requests to worker agents
   (`openai/gpt-oss-20b`). The workers act on a synthetic SQLite database through a typed executor. A
   rule-based checker counts executed policy violations. A refused request can be re-asked of another
   worker. We compare defenses: none; an exact shared ledger of refused requests; a text-similarity
   ledger (MiniLM, tau = 0.85); a lexical ledger and a scope ledger under wording change; a per-request
   intent screen; a "never re-ask" rule (computed from the none arm). We also test an adaptive LLM
   coordinator that may rephrase and re-route refused requests.
2. **Split-commit monitoring (commit monitor / "linking problem").** Inert toy attacks are split into 3
   commits inside streams of benign LLM-written commits to a fake 3-service repository. A gpt-5-mini
   monitor reviews each commit alone, or reviews linked groups jointly (boundary and dependency linkers,
   an oracle). There is an LLM rewriter attacker, a round-7 execution-validity check and a K = 1 merge
   check.

**Thesis: the cross-step part is the cheap part; the floor is per-step.** A shared exact refusal record
(or never re-asking) removes most re-ask violations against a scripted re-asker, and per-commit review
was enough for split commits. What remains is per-step: first-try compliance on new request types, an
intent screen that shares the worker's blind spots, rephrased requests that pass an exact record, and
commits rewritten to look ordinary.

## API setup

All model calls go through **OpenRouter** (`https://openrouter.ai/api/v1/chat/completions`). Keys are
read from the environment only; no key is in this repository.

```
cp .env.example .env      # fill in, then:
set -a; . ./.env; set +a
```
`OPENROUTER_API_KEY` is read first. `OPENROUTER_KEY_FILE` (a path to a file holding one raw key) is the
fallback. Both clients keep a spend cap (`CAP` in `planD/llm.py`; `CAP_USD` in `commit_monitor/src/llm.py`).
The Plan D client also writes a shared `planD/budget.jsonl` and `planD/rate_limits.json`.

## Reproduce each result (needs an API key unless marked "no API")

Run everything from the repository root. A new Plan D run writes `planD/runs/<UTC-timestamp>-<name>/`.
Model outputs at temperature 0.7 (Plan D) and with no temperature set (commit monitor) are not
deterministic, so a fresh run reproduces the design, not the exact numbers. The included
`episodes.jsonl` files reproduce the paper's numbers exactly (verified, see "Verification").

Costs are the provider-reported cost of the original run. Runtimes are wall-clock from run start to
`finish.json` and depend on provider rate limits.

## Caveats and withheld material

**Withheld (dual-use), commit monitor:**
- The attack chains: `src/attacks.py`, `src/attacks2.py` (hand-written attack hunks), `src/fix_attacks.py`
  and every `data/attacks/*.json` (attack commits with their diffs).
- The LLM rewriter: `src/llm_attacker.py` (its rewriting prompt) and its outputs
  `data/attacks/attacks_r6_llmadapt.json`.
- The rule-based adaptive attacker: `adaptive()` in `src/experiment4.py` is replaced by a stub that raises
  `NotImplementedError`. `experiment4/5/6.py`, `gen*.py`, `r6_llm_score.py`, `r7_*.py` and `analysis7.py`
  therefore cannot rebuild attack sequences from this release.
- LLM effect summaries and tags of attack commits (`results/r2_tags.json`, `r3_effects.json`,
  `r4_effects.json`, `r5_structured.json`, `r3_diagnosis.*`), and the free-text goal-check notes in
  `results/attack_validity.csv`, `r7_validity.json` and `r7_design_validity.json` (the booleans are kept).
- The response cache `cache/llm_cache.jsonl` (31 MB; holds every prompt and reply, including the
  attacker's) and the per-call logs `results/run_log.jsonl` and `spend_ledger.jsonl`.

The attacks are inert edits to a fake repository using reserved `.example` domains. PILOT_RESULTS.md
and the paper describe the attackers at a high level only. Researchers who need the chains for defensive
work can ask the authors via a GitHub issue on this repository.

**Not included, Plan D:** raw API call logs (`calls.jsonl`), `flagged.jsonl`, the shared spend ledger,
per-run `source/` snapshots (hashes are in `config.json`), the sprint handoff archive, and episodes for
the v1 runs. Kept: `episodes.jsonl` for the seven runs that a figure or recount reads (each under 5 MB;
synthetic data only; the `api_keys` table values such as `sk-sso-...` are fake strings in the toy DB).

**Known reproducibility gaps and caveats (carried from the paper and METHOD_FILLINS_ANSWERS.md):**
- Commit monitor headline "5% FPR" thresholds were set on the **held-out test benign set**
  (test-set-matched). Calibration-only detection is much lower (per-commit 0.39 NP / 0.21 conformal vs
  0.68). AUC is the main comparison.
- The calibration tail rests on one commit (B50v2, score 72, in 25/200 calibration sequences) and the
  held-out tail on one (X02s1, 68, 17/100). The oracle's 0.55 at 5% is a randomized tie-break (23/42
  attacks score 78; the deterministic cut gives 0.095).
- 31 of 126 LLM-rewritten commits have diffs byte-identical to the original (25 changed only the
  message; 6 chains are fully unchanged), so "rewritten" overstates the rewrite.
- No script produces `results/r7_design_validity.json` (the "37/42 hunks-only" number), and no code or
  saved result produces the round-6 leakage AUC 0.68. These numbers cannot be reproduced.
- 6 of the 65 "new" v3 benign commits duplicate earlier variants; 3 (B38v3, B56v3, B59v3) equal
  calibration commits.
- The monitor prompt was written using the 6 original chains (6 of the 42 test chains); the round-7
  filters were chosen after the test split was seen. Round 7 is exploratory, not pre-registered.
- `results/r6_score.log` ends in a crash; the final `r6_scores.json` came from an unlogged rerun after a
  one-line fix. Round-7 run order is inferred. No package versions were recorded at run time.
- Rounds 6-7 point estimates were audited (recomputed exactly from saved scores and cache, 0 imputed
  scores). Rounds 1-5 were not audited. Paper results marked † were not independently audited.
- Plan D: 6 trials; violations cluster in a few request types, so the request-type interval is the
  honest one. Host A vs host B absolute rates are not comparable. Text similarity was tested at one
  operating point (tau 0.85). One coordinator model, 3 trials, for the adaptive study.
- Some internal notes cite audit notes (A1-LM, A2-O, AMR, TS, REVIEW_P2, L3CALLS) that are
  not part of this release. L3CALLS (calls per arm, incl. screen calls) was counted from `calls.jsonl`, which is
  not released; `planD_analysis/ledger_metric_v3.py` reports worker and screen calls per arm from `episodes.jsonl`.
